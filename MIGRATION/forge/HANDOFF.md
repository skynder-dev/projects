> Источник: документы проекта в репозитории (`forge/README.md`, `forge/docs/CURRENT_STATE.md`, `NEXT_ACTION.md`, `ROADMAP.md`, `WORKLOG.md`, `forge/docs/migration_01/`). Я (Claude, сессия RevEng) эту программу **не запускал и не проверял**, а только прочитал документы. Всё, что ниже о состоянии, взято оттуда. Копии документов: `docs_snapshot/` рядом.

## 1. Что это

**Merch Forge** — локальная программа для Windows (PowerShell + WPF) для пути «рыночное исследование → идея мерча → макет → проверки → пакет для Amazon Merch → продажи». Цель: чтобы владелец прошёл путь сам, а его участие было только в субъективных или необратимых местах (выбор макета, оплата генерации, публикация).

Целевой процесс: Discover/Research → черновик концепта → обзор владельцем (KEEP / EDIT / REGEN / SKIP) → подготовка макета (без отправки) → импорт точного макета → принятие → проверки (метаданные, политика, IP) → пакет к публикации.

### Как устроено доказательство работоспособности
Каждый push в `forge/**` запускает workflow **forge-windows** на настоящем Windows (экран 1920×1080): стартовый preflight и самопроверка конвейера провайдера; самопроверка под Windows PowerShell 5.1 (118 проверок); управление настоящим окном кликами в пяти процессах (`create`, `restart`, `package`, `layout` на трёх ширинах с проверкой «нет английского на русских экранах», `offline` — поиск падений); установка из релизного ZIP (чистая установка, обновление поверх 054 с сохранением данных, запрет понижения версии, дневная копия). Результаты: ветка `forge-ci-results` (`latest/`). Данные в CI — условные (fixtures); ничего не публикуется.

## 3. Что НЕ доказано

- **Ни одного реального прохода владельца** «идея → макет → проверки → пакет → ручная загрузка → квитанция → CSV продаж». Это главный риск: всё проверено на условных данных.
- Реальный экспорт продаж Amazon Merch не использован: имена колонок не подтверждены на настоящем файле.
- Живой `discover_snapshot` не связывает заметки исследования с нишей, поэтому черновики пока получают 0 связанных заметок (закрыто на отказ, безопасно). Для исправления нужна правка сервера `forge-app`: **решение владельца**.
- Редкие технические сообщения (например, отклонённый результат воркера) могут остаться английскими в RU/ES.
- Статическая проверка и проверка на CI-Windows не равны проверке «на машине владельца»: границу доказательства всегда указывать точно.

## 4. Правила владельца

Из `forge/docs/migration_01/04_OWNER_RULES.md`, `ALEX_AUTONOMOUS_WORK_CONTRACT.md`, `NEXT_ACTION.md`:
- Не просить владельца нажимать GO и не согласовывать обратимые инженерные решения; решать и продолжать. Сбой: диагностика → исправление → повторная проверка → дальше.
- Не выводить творческое принятие из тишины или из «тест прошёл».
- **Без явного разрешения:** платная генерация изображений, публикация/подача товаров, запись в бэкенд (Supabase), принятие макетов за владельца, контакты с внешними людьми.
- Секреты не копировать в код, логи, пакеты, промпты и отчёты.
- Тёмно-оранжевую визуальную тему не менять без конкретного дефекта юзабилити; функциональность важнее косметики.
- Не строить продукт вокруг биографии владельца и личных контактов.
- Когда нужен ввод владельца, один компактный пакет вопросов, а не много перебиваний.
- **Рабочее соглашение (2026-10-09):** работать прямо в `main`, без pull request; каждый push в `forge/**` проверяется на Windows; зелёный → обновляется `forge-last-green`; красный → чинить вперёд сразу. Если у ChatGPT нет права писать прямо в `main`, это соглашение придётся пересогласовать.
- Замороженное не править: `forge/archive/` (054 каноническая, 050 откат) — только для чтения.

## 6а. Как запускать

Windows: распаковать релизный ZIP или взять `forge/app/`, запустить `START_077_MERCH_FORGE.vbs`. Установка и обновление проверяются тестом `Test-ForgeInstall.ps1` на CI. Локально Python 3 нужен для `tools/build_release.py`.

## 9. Мои наблюдения (по документам, не по запуску)

1. **Самая ценная часть проекта — Windows-CI на каждый push.** Она не зависит от того, какой ИИ пишет код. Сохраните её при переходе в ChatGPT и сделайте любой ИИ-правке обязательным условием зелёный `forge-windows`.
2. **Главный пробел — реальные данные.** Много слоёв проверки и четыре независимых ревью, но ни одного реального прохода. Я бы поставил шаг 1 из раздела 8 выше любых новых функций.
3. **Правки только через сборку.** Из-за `integrity.json` ручная правка файла в `app/` без пересчёта сумм сломает старт. Для ChatGPT без оболочки это значит: правки только через `build_release.py` на машине, где можно запустить Python и CI.
4. **Вопрос про «прямо в main»:** это соглашение было с Claude. Для ChatGPT/Codex чаще работает схема «ветка и pull request»; решите, какую оставить, и обновите `NEXT_ACTION.md`.
5. **Документ `forge/docs/migration_01/` описывает прошлую миграцию (в Claude).** Он устарел по состоянию (опорная точка там 054, сейчас 077), но его правила и ловушки актуальны.
