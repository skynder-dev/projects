# Поиск тем Social

`topics` выбирает темы по категориям заявителей из источника и объясняет каждый
балл. Команда не вызывает модель, не создаёт видео и ничего не публикует.
Новые модули используют только стандартную библиотеку Python 3.11.

Из корня репозитория проверки запускаются так (для старых тестов уже должны быть
установлены Pillow, pypdf и ffmpeg/ffprobe; новых зависимостей нет):

```sh
python -B social/.ci/run_social_concept_core.py
cd social
python -B -m unittest discover -s tests -t .
```

Далее команды выполняются из `social/`:

```sh
python -m socialreel topics --out runs/topics
python -m socialreel topics --out runs/topics-offline --fixture fixtures/grants_gov_normalized_20261003.json --as-of 2026-11-02
python -B -m unittest tests.test_topics -v
```

Первый запуск обращается к живому Grants.gov. Второй использует только указанный
файл. `--as-of YYYY-MM-DD` фиксирует дату оценки; без него берётся текущая дата UTC.
Одинаковые исходные файлы, дата и настройки дают одинаковый `topics.json` в
офлайн-режиме. Исходный файл сохраняется целиком в `source/topics_fixture.json`,
без пересборки JSON; его хеш не выдаётся за хеш исторического ответа API.

Формат fixture совпадает с существующими экспортами: JSON-массив объектов с
`normalized_facts` и необязательным `source_url`. Допустима также обёртка
`{"records": [...]}`. Содержимое уже нормализованного экспорта не восстанавливается
до якобы исходного ответа API. Неизвестные поля остаются неизвестными.

Настройки по умолчанию находятся в `topics_config.json`. Их можно переопределить
объектом `topics` в файле, переданном через `--config`:

```json
{
  "topics": {
    "max_detail_fetch": 10,
    "seen_file": "topics_seen.json",
    "timing": {"min_days": 14, "max_days": 120}
  }
}
```

Файл использованных тем — JSON-массив ID, например `["359671", "364020"]`.
Относительный путь считается от папки конфигурации. Отсутствующий файл означает
пустую историю и отмечается в результате; команда сама историю не дополняет.
`seen_file: null` отключает историю. Повтор получает на 10 баллов меньше, но не
удаляется. Некорректный существующий файл вызывает ошибку, а не сбрасывает историю.

Рубрики `help_people` и `small_business_nonprofit` содержат несколько ключевых слов
и коды для фильтра `eligibilities` официального поиска. Таблица кодов восстановлена
по известным категориям Grants.gov, описания сверены с примерами репозитория;
цифровые соответствия помечены **needs check against Grants.gov docs**. Живые
документация и API при разработке не проверялись. Не следует принимать поисковый
фильтр за доказательство подходящей категории конкретной записи.

Сначала записи объединяются по ID и предварительно оцениваются по доступным
полям поиска. Явные институциональные категории и истёкшие сроки исключаются.
Подробности загружаются для первых N оставшихся ID — по умолчанию 10 всего на
запуск, не на ключевое слово. Финальная оценка пересчитывается по подробностям.
Для отброшенных из-за лимита кандидатов сохраняется причина `detail_limit`;
дополнительного добора после исключения подробной записи нет. В fixture все
подробности уже локальные, поэтому лимит сетевых запросов не применяется.

Одна возможность появляется в рейтинге один раз. Если подходят обе рубрики,
выбирается рубрика с большим баллом аудитории; при равенстве — первая в настройках.
Все поисковые попадания остаются в `discovered_via`. Равные итоговые баллы
упорядочиваются по строковому ID. Строки и словари исходных категорий, HTML и
полные условия не сокращаются и не переписываются.

Оценка складывается из аудитории (до 40), срока (до 25), конкретики (до 25),
новизны (до 10) и штрафа за неизвестные данные (по 2 за поле). Конкретика учитывает
положительную сумму отдельной выплаты, полный текст условий и описание; общий
бюджет программы не подменяет сумму выплаты. Сроки меньше 14 дней или больше
120 дней получают меньше баллов, истёкшие записи исключаются. Неизвестная дата
сохраняется без догадки и не получает баллов срока. Итог может быть отрицательным.

Исключаются записи, где известные категории — только учебные учреждения,
государственные/муниципальные/племенные органы или другие институции. Записи без
подтверждённой целевой категории также исключаются; слова о малом бизнесе в
описании сами по себе не подтверждают категорию заявителя. `Others` не означает
«любой человек». `Unrestricted` допускается с меньшим баллом и с сохранением
полного текста ограничений. Это оценка метаданных; соответствие конкретного
человека всем условиям и ограничениям США не доказано.

В `topics.json`: `topics` — рейтинг, `excluded` — исключения, `score.components` —
баллы и причины, `score.missing_data` — пробелы, `provenance` и `field_provenance` —
файлы снимков, SHA-256 и поля источника. `sources` содержит квитанции всех запросов.
В live-режиме снимки сохраняет существующий `GrantsGovClient` без изменения байтов.

Пробному генератору можно передать рейтинг из живого или офлайн-запуска:

```sh
python -I trial/concept_trial.py . runs/concept-from-topics --topics runs/topics/topics.json
python -I trial/concept_trial.py . runs/concept-from-topics http://127.0.0.1:11435 --topics runs/topics/topics.json
```

Он берёт ID первой строки и заново загружает её подробности из Grants.gov, затем
использует прежний диагностический путь локальной модели. Пустой или неправильный
файл завершает этап источника с ошибкой, без запасного поиска. Без `--topics`
остаётся прежний поиск `community`. Эти команды пробного генератора не офлайн:
при разработке проверялся только этап выбора источника с поддельным транспортом.

Офлайн-тесты проверяют механизм и сохранность данных. Они не подтверждают поведение
живого API, пригодность тем для зрителей или качество концептов модели.
