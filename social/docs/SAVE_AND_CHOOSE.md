# CODEX_02: сохранить идеи и выбрать одну

Команды `concepts` сохраняют готовый `trial.json`, показывают варианты, записывают
явный выбор владельца или отклонение всех вариантов, позволяют исправить текст и
подготовить файлы для чтения на телефоне и передачи другим проектам. Все команды
работают локально, без модели, сети и новых зависимостей.

## Пример на синтетических данных

Из `social/`, PowerShell, Python 3.11:

```powershell
$saved = python -B -m socialreel concepts import fixtures/concept_trial_synthetic.json --store runs/concept-store-demo | ConvertFrom-Json
$job = $saved.job_id
python -B -m socialreel concepts list --store runs/concept-store-demo
python -B -m socialreel concepts show $job --store runs/concept-store-demo
$before = python -B -m socialreel concepts show $job --store runs/concept-store-demo | ConvertFrom-Json
python -B -m socialreel concepts decide $job --pick C2 --note 'Выбираю второй синтетический вариант.' --revision $before.revision --store runs/concept-store-demo
python -B -m socialreel concepts export $job --md runs/concept-review-picked.md --store runs/concept-store-demo
python -B -m socialreel concepts handoff $job --out runs/concept-handoff-demo --store runs/concept-store-demo
$picked = python -B -m socialreel concepts show $job --store runs/concept-store-demo | ConvertFrom-Json
python -B -m socialreel concepts edit $job C2 --field hook --value 'An exact owner edit.' --revision $picked.revision --store runs/concept-store-demo
python -B -m socialreel concepts export $job --md runs/concept-review-edited.md --store runs/concept-store-demo
$edited = python -B -m socialreel concepts show $job --store runs/concept-store-demo | ConvertFrom-Json
python -B -m socialreel concepts decide $job --reject-all --note 'После правки отклоняю все варианты.' --revision $edited.revision --store runs/concept-store-demo
```

Fixture явно синтетический: это проверка механизма, не живые правила программы и
не результат запуска модели. Для настоящего результата замените путь на свой
`trial.json`. Папка хранилища задаётся явно каждой команде. Job ID возвращается
импортом; это первые 32 символа SHA-256 исходных байтов файла. Повтор тех же байтов,
даже под другим именем и после правок, — no-op с сообщением `Already imported`.
Другая сериализация того же JSON считается другим исходным файлом.

`list` выводит строку на задачу: ID, дату импорта, заголовок источника, состояние,
число вариантов и последнее решение. Переносы строк заголовка отображаются как
`\n`, чтобы задача оставалась в одной строке. `show` выводит полный JSON без
сокращения: исходный trial, запрос и его хеш, ответ модели, старую и пересчитанную
диагностику, факты и происхождение, все ревизии и решения, текущий выбор и
неприкреплённые записи после сбоев. Старые исследовательские задачи не переименовываются
и не становятся импортированными результатами.

## Решения и правки

При импорте ничего не одобряется. Сохранённые `accepted_by_owner` и диагностика
модели остаются исходными данными. Программа сверяет хеш запроса, его факты,
полный контекст условий, входную идентичность и схему, затем повторно вызывает
неизменённый `concept_core.validate`. Это проверка структуры и известных ссылок,
а не качества, актуальности, фактической истинности или успешного допуска модели.
Импорт с ошибкой сохраняется для просмотра; выбирать такой результат нельзя.

`decide` требует ровно один вариант `--pick C1/C2/C3` либо `--reject-all`, а также
непустую причину `--note`. Выбор возможен только для полного структурно корректного
результата с привязанными фактами. Явный ответ `no_supported_concept` можно
просмотреть и отклонить целиком; выбрать отсутствующий C1 нельзя.

`edit` изменяет одно из пяти текстовых полей: `viewer_question_ru`, `angle_ru`,
`what_viewer_learns_ru`, `not_answered_ru`, `hook`. IDs, ссылки на факты, запрос,
источник и исходный ответ модели не редактируются. Поля проверяются прежним
контрактом; слишком длинный текст получает отказ, без обрезки. Все остальные
варианты и прежний текст остаются в истории.

Каждый импорт, решение и правка создают неизменяемую ревизию с SHA-256 и ссылкой
на предыдущую. `revision` — последняя операция; `content_revision` — точная
ревизия текста идеи. Решение ссылается на `content_revision`. После любой правки
старое решение отображается как `decision_stale`, не переносится на новый текст
и не разрешает handoff. Новый явный выбор необходим и после правки выбранного,
и после правки другого варианта.

`--revision HASH` у `decide` и `edit` позволяет передать хеш, увиденный ранее в
`show`: если кто-то успел сохранить новую операцию, запись отклоняется с кодом 2.
Без этого параметра команда берёт текущую ревизию в начале выполнения и всё равно
проверяет её перед записью. Одновременные записи сериализуются общей блокировкой;
тихого слияния изменений нет. Причины и текст полей сохраняются дословно.

`owner_approved: true` в представлении появляется только после актуального явного
выбора, с областью `editorial_choice_only`. Это не разрешение публикации:
`publication_approved` остаётся false. Старое поле журнала `approved` также остаётся
false, сохраняя прежнюю границу допуска. Владельческий контекст отдельно помечен
как непроверенное предпочтение и сам ничего не одобряет.

## Файлы для чтения и передачи

`export --md PATH` создаёт Markdown на русском: источник, ссылка, срок, каждый
вариант с вопросом, подходом, пользой для зрителя, границами ответа, первой фразой,
опорными фактами и состоянием решения. Тексты полей и цитаты не переводятся и не
сокращаются. Видно, что прежний выбор устарел после правки.

`handoff --out DIR` создаёт `DIR/<id>.json` по договорённости
[shared/BOARD.md](https://github.com/skynder-dev/pc/blob/main/shared/BOARD.md):

```json
{"id": "...", "topic": "...", "audience": "...", "script": "", "source_url": "...", "facts": []}
```

Он доступен только при актуальном явном выборе. `topic` — вопрос выбранной идеи,
`audience` — переданное описание аудитории или её тег (пусто, если неизвестно).
Сценария пока нет, поэтому `script` пустой; hook не выдаётся за сценарий. `facts`
содержит только факты, которые цитирует выбранная идея, с точной цитатой или
указателем поля и SHA-256 снимка. Контекст условий цитируемого факта тоже сохраняется.
Локальные пути снимков исключаются из передачи. Неизвестная ссылка или отсутствующая
контрольная сумма дают отказ до создания файла. Ссылка по ID программы не угадывается.
Хеши привязывают сохранённые данные, но не доказывают текущие правила программы.

ID передачи включает Job ID, полный хеш явного решения и ID варианта: разные
решения не перезаписывают прежний файл. Markdown и JSON создаются без замены
существующего другого содержимого. Повтор одинаковых байтов — no-op; для новой
страницы после правки укажите новый `--md`. Перед записью экспорт ещё раз проверяет
ревизию под общей блокировкой. Команда только пишет файл в указанную папку.

## Хранение и восстановление

Используется существующий `ConceptStore`: тот же `queue.sqlite3`, таблица `jobs`,
проверка Job ID, `motion_lock` и атомарная запись из `concept_storage`. Нового
параллельного хранилища нет. Импортированные задачи имеют отдельное состояние
`concept_trial_import` и не ставятся в очередь выполнения. В папке задачи:

```text
concept_results/trial.json             # точные исходные байты
concept_results/revisions/<sha>.json   # неизменяемые импорт/правки/решения
concept_results/head.json              # атомарный указатель на последнюю ревизию
```

Перезаписываются только служебный указатель и индекс SQLite; содержимое истории
не заменяется и не удаляется. Решения встроены в ту же цепочку ревизий, а их связи
проверяет существующий `concept_decision_ledger.verify_events`. Проверки прежнего
файлового журнала не ослаблены. `concept_owner_context` читается отдельно прежним API.

Сбой fsync или замены head оставляет прежнюю цепочку читаемой. Незавершённые
ревизии показываются в `uncommitted_revisions`; они не становятся выбором и не
удаляются автоматически. Явная следующая запись от текущего хеша сохраняет новую
операцию. Прерванный первый импорт виден как `import_incomplete`: повторите тот же
импорт. Повреждённые байты не исправляются перезаписью. Цепочка ограничена 1000
ревизиями; превышение даёт отказ, без удаления истории.

## Проверки

Из корня: `python -B social/.ci/run_social_concept_core.py`.
Из `social/`:

```sh
python -B -m unittest tests.test_concept_choose -v
python -B -m unittest discover -s tests -t .
```

Офлайн проходят 88 тестов ядра и полный набор 233 теста, включая 23 новых.
Проверены CLI round trip, оба контракта, повторный импорт, все варианты и точные
поля экспорта, выбор и отклонение, правки, устаревшие/одновременные записи, сбои
fsync и head, неполный импорт, сохранность исходного ответа, недоверенная отметка
одобрения, отсутствие URL/SHA и гонка перед handoff. Новые тесты блокируют сеть.
Живые источники, модель, успешный допуск, смысловое качество идей и приложения
других проектов в этом задании не проверялись.
